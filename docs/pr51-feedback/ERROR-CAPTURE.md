# Error capture: `rethrowError` + route error boundary (PR 51 feedback, G2)

Owner direction: 4036682063 ("this above error should be captured by the event bus... error boundaries should be employed so that no error goes un-captured") and 4036756544 ("a `rethrowError` helper which populates event bus fields and then throws to a parental boundary"). Source anchor: the not-found throw inside `makePayment` in `app/routes/invoices.tsx`.

## The helper — `app/utils/events.ts`

`rethrowError(bus, event, error)` publishes the failure, then throws the original error toward the parental boundary:

- Severity is always `"error"`; `message` defaults to `errorMessage(error)`; the caught value wins `context.error`, merged with the caller's context and normalised by the existing publish path.
- Exactly-once: a module-level `WeakSet` of already-published errors backs `hasBeenPublished(error)`. A second helper call — or a parental catch/boundary that publishes through the helper — for the same caught value is skipped. The WeakSet marks objects only; thrown primitives cannot be marked, so helper sites always pass `Error` objects.
- The throw is the original object, never a wrapper, so parental catches keep their `instanceof`/message checks.
- The publish half is split out as `publishError(bus, event, error)` (publish + mark, no throw): it derives the message, normalises `context.error`, marks the WeakSet, and skips already-published values. Callers that publish inside a catch while keeping control of control flow use it directly; `rethrowError` is `publishError` + `throw error`.
- Known edge: exactly-once is identity-based. React may attempt an error render more than once, and a component that constructs a fresh `Error` per attempt can produce one event per attempt. `rethrowError` sites — the same object rethrown toward the boundary — are the guaranteed exactly-once path.

## Three capture paths

React Router error boundaries catch loader, action and render errors. They do not catch errors thrown from async event handlers, so "no error goes un-captured" needs both shapes:

1. **Handler path** — the flagged site. `makePayment`'s not-found throw (`app/routes/invoices.tsx`) is `rethrowError(eventBus, { type: "payment", context: { invoiceId, action: "failed" } }, new Error(...))`: publish at the source, throw to the parental catch, `PaymentModal.submit`. That catch runs `publishError` as its safety net — it publishes only when `hasBeenPublished(e)` is false (checked inside the helper), so helper sites publish exactly once and throws that did not go through the helper (e.g. the invalid-amount guard) stay captured.
2. **Route path** — `app/routes/invoices.tsx` exports an `ErrorBoundary` (`Route.ErrorBoundaryProps`). React Router delivers the error through `useRouteError` (the `error` prop is the framework-mode fallback; never a conditional hook). The boundary defers one `publishError` with `queueMicrotask` — bus listeners such as Toaster may call `setState`, which is illegal in another component's render — then rethrows the original error, including `isRouteErrorResponse` values. A boundary's own render throw propagates to the ancestor boundary, so the root boundary renders the visual fallback. `app/routes.ts` is unchanged: a per-route module `ErrorBoundary` export is the React Router v7 framework-mode mechanism.
3. **Terminal path (root)** — `app/root.tsx`'s `ErrorBoundary` publishes the error and renders the fallback; it never rethrows, because there is no ancestor boundary to delegate to. The publish rides `queueMicrotask` + `publishError`, so a route boundary's already-published error wins the microtask FIFO (WeakSet shared) and root adds nothing — pinned by test in `app/routes/root.test.tsx`, including the real invoices→root composition and a boundary-less child route (the `clients`/`invoice` routes carry no boundary; root is their capture). Navigational 404s skip the publish at root: a framework "no route matched" is an expected outcome, not a product failure — the fallback page is its capture, and a never-auto-dismissing error toast per mistyped URL is noise. The owner's flagged error (the `makePayment` not-found throw) is unrelated to this: it is a handler-path error, captured at the source. Asymmetry note: the invoices route boundary publishes its route's own 404 responses; root skips only framework-level ones. The publish is client-only (`typeof window !== "undefined"`): the server's bus has no consumer, so SSR failures stay on the SSR error path.

## Coexistence with per-site try/catch

Error-severity catch bodies now route through `publishError` (the ledger-named sites — `Autosave`-adjacent `deleteInvoice`/`makePayment` db-failure, `SaveClientModal`, the PaymentModal safety net — plus the same shapes in `clients.tsx` and `invoice.tsx`). The `try/catch` wrappers necessarily remain: React Router boundaries cannot catch async event-handler throws, so a local catch is the only capture point there — the consolidation is in the publish, not the catching. The conversion is payload-neutral: the bus normalises `context.error` to a string on both the raw-publish and helper paths (`withNormalisedError`), and `publishError` forces severity `"error"`, matching the old explicit severity; explicit messages are preserved. The only reachable copy change is the PaymentModal non-`Error` fallback, which now renders `String(e)` instead of `"Payment failed"` — both reachable throw sites produce `Error` objects. Warning/debug catch sites (`Autosave`, the load-failure guards, `db.ts`'s storage warning, `Inputs`' debug publish) deliberately stay raw publishes: `publishError` forces severity `"error"`, so converting them would flip recoverable warnings into never-auto-dismissing red toasts.

## Event vocabulary

`EVENT_TYPES` gains `app` — harness-level failures that belong to no single domain (the root boundary's captures). This supersedes the earlier note on this card that the union is not extended: that deferral was worker-authored, while ledger G1a (owner verdict) defines an open domain-key union; the ledger wins, and the addition is one revertible commit. Domain keys still carry everything with a domain (`invoice`, `payment`, `client`, ...); root's events use `app` with `context.action: "route-error"` and `context.boundary: "root"`, and the invoices route boundary keeps its route-scoped `invoice` events. Boot diagnostics stay as they are (`app/utils/eventLogging.ts`, non-replayable console sink); events published while no replay-capable surface is subscribed buffer for replay (cap 100), so a route error before the Toaster mounts is still delivered.
